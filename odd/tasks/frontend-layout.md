## Log

- L1: Inventory (read-only explore, 2026-11-03, branch `test/rtl-mount-tests`). Config: only `apps/frontend/tsconfig.json:7` (`"@/*": ["./*"]`) needs a change; `app.json` (expo-router plugin without `root`), `metro.config.js`, `app.config.ts`, ESLint, root scripts, lint-staged, bunfig and CI need none; there is no `babel.config.js`. Expo Router: "The src/app directory takes higher precedence than the root app directory" (https://docs.expo.dev/router/reference/src-directory/); an existing project moves `app/` to `src/app` and points `@/*` at `./src/*`. Moving `app/`, `core/` and `components/` together keeps their relative imports valid; 98 imports use `@/`. What breaks: 23 relative imports into `assets/` (one level deeper), 66 tests that read source by path (11 in `tests/__tests__`, 20 in `tests/orders`, 5 in `tests/prepare`, 2 in `tests/checkout` and `tests/dependencies`, 20 colocated in `core/`, 8 in `components/`; some use `process.cwd()` and run only from the repo root), and `core/legacyWalletRemoval.test.ts` (`SCANNED_DIRS`). Domain map: `components/features/` has 17 folders (144 files); `core/hooks` (69) and `core/utils` (51) split by domain; `core/auth` holds 13 `*.logic.ts` plus global providers. Violations of `shared -> features -> app` today: `core/auth/AuthModalProvider.tsx:18` -> `components/features/auth/AuthModal`; `components/ui/MaintenanceScreen.tsx:12` -> `components/features/home/sharedStyles` (also used by shop and product); 10 feature-to-feature imports in 9 files (product and shop cards use `home/sharedStyles`; home and shop sections use `ProductCard`; `OrderActionCard` uses payments; `ProfileActionsBar` uses address); 11 `core/hooks` import `components/auth/AuthProvider`. Barrels: `components/features/home/sections/index.ts`, `components/features/shop/index.ts`. Order screens over 700 lines: `app/profile/orders/[id].tsx` 1010, `prepare/[id].tsx` 845. 75 files in `__tests__/` folders, 50 in `apps/frontend/tests/`.
- L2: Decisions for the maintainer, with the recommendation. (A) `AuthProvider`, `AuthModalProvider`, `CaptchaProvider` and `SystemGuard` are app-wide session plumbing that hooks in every domain read: recommend `shared/lib/auth/`, with `AuthModal` (the modal the provider opens) in `shared/ui`; the auth screens and `*.logic.ts` go to `features/auth`. (B) Code that several features use moves to `shared`: `home/sharedStyles` -> `shared/theme`, `ProductCard` and `ProductMiniCard` -> `shared/ui` (home, shop, search and product all list products). (C) A feature that needs another feature's screen part gets it through the route instead (`OrderActionCard` -> payments, `ProfileActionsBar` -> address): the route composes both. Where that is not practical, the piece moves to `shared/ui`. Unclear owners, decided per domain commit: `onboarding` (Connect copy) -> payments; `settings` stays its own feature; `users` (reviews) -> profile; `shop` and `search` stay separate.
