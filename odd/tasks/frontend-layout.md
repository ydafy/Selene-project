Expo Router: "The src/app directory takes higher precedence than the root app directory" (https://docs.expo.dev/router/reference/src-directory/); an existing project moves `app/` to `src/app` and points `@/*` at `./src/*`. Moving `app/`, `core/` and `components/` together keeps their relative imports valid; 98 imports use `@/`. - L2: Decisions for the maintainer, with the recommendation. (A) `AuthProvider`, `AuthModalProvider`, `CaptchaProvider` and `SystemGuard` are app-wide session plumbing that hooks in every domain read: recommend `shared/lib/auth/`, with `AuthModal` (the modal the provider opens) in `shared/ui`; the auth screens and `*.logic.ts` go to `features/auth`. (B) Code that several features use moves to `shared`: `home/sharedStyles` -> `shared/theme`, `ProductCard` and `ProductMiniCard` -> `shared/ui` (home, shop, search and product all list products). (C) A feature that needs another feature's screen part gets it through the route instead (`OrderActionCard` -> payments, `ProfileActionsBar` -> address): the route composes both. Where that is not practical, the piece moves to `shared/ui`. Unclear owners, decided per domain commit: `onboarding` (Connect copy) -> payments; `settings` stays its own feature; `users` (reviews) -> profile; `shop` and `search` stay separate.

Research: Expo supports `src/app` out of the box and the SDK 55 template already ships `src/` (https://docs.expo.dev/router/reference/src-directory/); Expo's structure guide (updated 2026-01-07) has every route return a screen component and makes kebab-case the default file naming (https://expo.dev/blog/expo-app-folder-structure-best-practices); bulletproof-react uses `shared -> features -> app`, "compose different features at the application level", no barrel files, and enforces it with ESLint `import/no-restricted-paths` (https://github.com/alan2207/bulletproof-react/blob/master/docs/project-structure.md). Feature-Sliced Design (`entities/` layer) was considered and not adopted: two product cards do not justify another layer. Decisions: (A) session (`AuthProvider`, `useAuth`) and the `useAuthModal` contract go to `shared/lib/auth`; the modal UI, its provider and `CaptchaProvider` go to `features/auth`, mounted by `src/app/_layout.tsx`; `SystemGuard` and `MaintenanceScreen` go to `shared/ui` (this replaces the L2 idea of `AuthModal` in `shared/ui`, which would pull the login forms into `shared`). (B) `ProductCard` and `ProductMiniCard` go to `shared/ui/product`, `getSharedStyles` to `shared/theme`. (C) routes compose cross-feature pieces; otherwise the piece moves to `shared/ui`. Thin routes import one screen from `features/<domain>/screens`. Alias: `@/*` -> `./src/*` and `@/assets/*` -> `./assets/*`. File names: kebab-case for every file except Expo Router route files, whose names are URLs; each file is renamed in the same `git mv` that moves it (`docs/conventions.md`, "File naming"); reason: Windows and macOS ignore case and the Linux CI does not. Dependency rule: also in ESLint (`import/no-restricted-paths`), approved by the maintainer ("si, suma eslint"), in G1. Outside the frontend: `apps/admin-web` has the same split by type (`pages/`, `components/features/`, 24 domain hooks in `hooks/`, `services/`) and gets the same layout as a new roadmap item after #134; the root layout (`apps/*`, `packages/*`, `supabase/`, `docs/`, `e2e/`, `bruno/`, `scripts/`) stays, with no Turborepo or Nx; the untracked `apps/backend/` (only a `node_modules` left after `odd/tasks/repo-hygiene.md` S1) was deleted locally; the root `tests/` moves in G3.
