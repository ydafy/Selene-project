- L2 (research, 2026-11-09): Declarative Schemas 2.0 (pg-delta, pre-1.0, on by default from CLI 2.119). `supabase db schema declarative generate` writes one file per object under `supabase/schemas/<schema>/...` plus `_cluster/`; `_custom/` is hand-written SQL for kinds pg-delta does not manage. `supabase db schema declarative sync -f <name> --no-apply` diffs the migration history against `schemas/` and writes a migration; `db diff` compares the live database with a shadow built from migrations and never reads `schemas/`; `schema_paths` is ignored. `db reset` and `db push` still apply `migrations/`. Not captured: data, buckets, own functions and indexes inside `auth` and `storage`, casts, operators, parameter ACLs. Renames come out as drop plus add. The docs give no exit code for "no changes". Sources: https://supabase.com/docs/guides/local-development/declarative-database-schemas, https://supabase.com/docs/guides/local-development/diff-engines. Repository: no `supabase/schemas/`, no `[db]` section in `config.toml`, no migration calls `pg_net` or `cron.schedule`. #275 (another session) converts `supabase/queries/__tests__/connectMoneyFlowGuards.test.ts` and `payout-release-amount-contract.test.ts`; PR 2 leaves those two to #275.
