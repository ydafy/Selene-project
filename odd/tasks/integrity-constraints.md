# Integrity constraints and naming

Roadmap #299, item 9 (#308). Worktree `supabase-health`, branch `feat/integrity-constraints` from `origin/main` `73403d40`. Three PRs: A constraints (T1-T6), B naming (T7-T10), C lowercase product status values (T11). One commit per task, each with its test first; a commit that touches money, SQL security or a contract is its own native review slice. Plan approved on 2026-11-14 (L3, L4).

## Specs

- S1. From #308, done when: "Each rule has a constraint and a pgTAP test that a violating write fails."
- S2. From #308: "`profiles_private.role` as an enum or a CHECK (it is the admin trust boundary)." Decision: enum `user_role` with values `user` and `admin`, NOT NULL, default `user` (L4). `profiles_private.status`, `stripe_onboarding_status` and `updated_at` are NOT NULL.
- S3. From #308: "NOT NULL where a value is always expected (for example the `order_items` amounts, `orders.currency` and timestamps, `notifications.read`, the `is_default` flags)." Money tables (`orders`, `shipments`, `order_items`, `connect_payout_runs`, `system_settings`) get NOT NULL on always-expected columns and CHECKs on their domains: cents and counters `>= 0`, hours `> 0`, `trusted_active_limit >= novice_active_limit`, `orders.currency = 'MXN'`, `shipping_payer` in (`buyer`, `seller`). From the #308 comment: "The money rates (`service_fee_pct`, `insurance_rate`) and the cents and hours columns should be NOT NULL with CHECK ranges".
- S4. The other tables (`profiles`, `products`, `addresses`, `notifications`, `admin_user_notes`, `admin_audit_logs`, `push_deliveries`, `category_configurations`, `webhook_dlq`, the `internal` counters) get the same treatment: rating 0..5, totals and attempts `>= 0`, Mexican zip codes five digits.
- S5. From #308: "Partial unique indexes: one default address and one default payment method per user, one review per shipment; a unique `(provider, delivery_id)` on `webhook_deliveries` if it is missing." One default live address per user. One review per shipment: unique `(reviewer_id, shipment_id)`, `reviews.shipment_id` NOT NULL, and the `(reviewer_id, product_id)` unique dropped so a repeat purchase can be reviewed (L5). `webhook_deliveries` already has the unique key; `payment_methods` is dropped by #309, so it gets no new index.
- S6. From #308: "Foreign keys: `ON DELETE RESTRICT` for money and shipment history, `CASCADE` only for user-owned preferences; user references point to `profiles`." A pgTAP guard pins the actions.
- S7. From the #308 comment: "`updated_at`: `system_settings.updated_at` exists but nothing updates it; check every table with an `updated_at` and use one trigger function for all of them." A pgTAP guard fails when a table with `updated_at` has no trigger.
- S8. From the #308 comment (#307 notes): "These columns already hold integer cents but have no `_cents` suffix": `shipments.shipping_cost`, `connect_payout_runs.amount`, `connect_payout_run_shipments.net_payout`. They become `*_cents` and `bigint`, renamed with `RENAME COLUMN` (no drop plus add).
- S9. From the #308 comment: "The admin RPCs `fn_admin_toggle_verified_seller` and `fn_admin_update_user_status` take a `p_admin_id` argument they never use for authorization (they correctly check `is_admin()` on the session). Drop it so the contract does not suggest the client chooses the admin."
- S10. From #308: "One index name convention and one enum convention (lowercase values, no `_enum` suffix), written in `docs/conventions.md`." Enums `order_status_enum` and `product_status_enum` lose the suffix. Existing index names stay; the convention applies to new indexes (L4).
- S11. `product_status` values become lowercase in the database and in every client, function and test that uses them (PR C, L4).
- S12. Out of scope: `disputes` (#261, finding #571), `reports` (#298), `payment_methods`, `system_logs`, `blocked_users` and the shipment event tables (#309), the reviews flow and UI (#339, its own worktree).
