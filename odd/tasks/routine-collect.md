# Routine collect script

`bun run routine:collect`: one read-only script that collects the weekly routine's data (`docs/maintenance.md`) and prints a short summary, so the agent reads one report instead of about 15 raw outputs. Roadmap #715, item 4, issue #719. Item 5 (#720) points the routine at the script.
Branch `feat/routine-collect`, main checkout. Three work-unit commits (S5), one PR that closes #719.

## Specs

- S1 (#719): "Add `bun run routine:collect`, a read-only script that prints the routine's data as a short summary, so the agent reads one report instead of about 15 raw outputs (the 2026-11-25 run read about 40 KB of JSON per Supabase advisor call)."
- S2 (#719): "It collects what `docs/maintenance.md` runs today with `gh`: the dependency workflow runs of the week and the report issue's summary line; draft advisory count and ages (IDs and severity only, never descriptions); open secret scanning alerts; new issues of the week; Go-live count and its change; critical and high issues; findings without a priority (including the title check of item 2); stale issues; PRs older than 7 days; failed runs on `main`; `agent-mistake` issues of the week; active worktrees with their lockfile changes."

- L3 (agreed design, 2026-11-27): the script lives in `scripts/dev/` (the maintainer runs it, not CI). It follows the `Collectors` pattern of `scripts/ci/dependency-report.ts`: collectors run `gh`, `git`, and `supabase` and return raw text; pure functions build each section, and tests pass canned text. It never starts a workflow, edits an issue, or writes a file. It decides only what a command can compute (a work job ran since Sunday, a later green run on `main`); what needs judgment, such as whether an `agent-mistake` comment is new evidence, it lists for the agent. A failed collector prints `Could not check: <command>: <error>` in its section, the other sections still run, and the script exits 1. Draft advisories are read with a `--jq` filter that keeps only `ghsa_id`, `severity`, and `created_at`, so descriptions never reach the script. "Go-live change" comes from history (issues created and closed in the Go-live milestone in the last 7 days), because the script keeps no state between weeks. Output and identifiers are English; the agent writes the Spanish report.
