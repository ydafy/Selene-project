# Guard payout progress conflict parking

## Objective
Prevent a stale payout-progress rejection from parking a newer complete, same-payout paid projection, without hiding a genuine mismatch, incomplete paid state, or late paid-to-failed reversal. Preserve immutable event evidence and the terminal/shipments atomic RPC.

## Evidence and uncertainty
Fresh sandbox run `acd3e0e3-8fb1-4673-bb89-d501a4ec7e6e` has observed Stripe paid, local paid mapping and shipment payout ID, but is parked `reconciliation_needed/action_required` with `PAYOUT_STAGE_PROJECTION_CONFLICT`. Its exact first rejected RPC state is not in retained logs; four same-second event receipts alone cannot establish this race as its specific cause. A source-level race exists between stage-RPC refusal and the subsequent run-ID-only park, which may overwrite a later paid projection. A complete paid run already held by the stage RPC would return TRUE under the latest migration; this task fences the remaining cross-RPC gap rather than weakening the stage/terminal guards.
