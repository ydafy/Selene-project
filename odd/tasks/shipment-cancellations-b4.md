- L11 — B4.3 design (pure logic plus thin I/O in `supabase/functions/_shared/envia-carrier-cancellation.ts`; no handler wiring, that is B4.4). Reuses `resolveEnviaRuntimeConfiguration` (`_shared/envia-shipping.ts`), `extractEnviaPollingObservations` (`_shared/envia-tracking-ingestion.ts`) and `normalizeEnviaTrackingStatus` (`_shared/envia-tracking.ts`); endpoints `ship/generaltrack/` (as `track-shipments`) and `ship/cancel/` (https://docs.envia.com/reference/cancel-shipment.md: body `carrier`, `trackingNumber`; 200 `meta: "cancel"`, `data.trackingNumber`, `data.balanceReturned`, `data.balanceReturnDate`). (a) Fresh tracking for one tracking number -> `scanned` when any observation's normalized transition is `shipped` or `delivered` (the carrier has the package; `fn_record_tracking_event` will advance the shipment); `unscanned` only when there is at least one observation and every status is one of `created`, `pending`, `information`, `n/a`; anything else (no observations, `canceled`, exceptions, unrecognized statuses, request failure, invalid response) -> `unknown` (R10: fail closed). Observations are also returned so B4.4 can record them through `fn_record_tracking_event`. (b) Cancel classification: `accepted` only for HTTP 2xx, `meta` `cancel`, `data` object and `data.trackingNumber` equal to the requested one; `balanceReturned` true only when the field is boolean `true` (anything else = not returned, the conservative loss); `balanceReturnedAt` an ISO string only when `balanceReturned` and the date parses, else null. `unavailable` (nothing happened at the carrier, nothing is recorded, retry next run): HTTP 401, 403, 429, or missing/invalid Envia configuration before any request. `refused`: any other 4xx whose body carries an Envia error (`meta` `error`, or an `error` field) and no matching `data.trackingNumber`. `ambiguous`: thrown fetch, timeout, 5xx, unparsable body, a 2xx without the accepted shape, or a 4xx without an error body. Each call has a timeout (AbortSignal). Never log the token, the request headers or the raw provider body; log only status, `meta` and the Envia error code.
