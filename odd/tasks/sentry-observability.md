# Sentry observability (backend)

Errors from Edge Functions and missed or failed cron runs reach the maintainer by email, instead of sitting in logs nobody reads.
Scope: Supabase Edge Functions and pg_cron jobs. The mobile app waits for the beta.

## Specs

- S1: "okey entremois con sentryu entronces" — Sentry is set up for the backend, at a minimal Selene level (free plan, no overengineering).
- S2: Plan approved with "okey, dale.": the official Sentry MCP, read-only, in `~/.gentle-shell/agent/mcp.json`, authenticated by OAuth, with write tools hidden (same pattern as the Supabase and Stripe MCPs). The `npx @sentry/agent-plugin install` command is not used.
- S3: Edge Functions report unhandled errors to Sentry with the official Sentry SDK; the DSN lives only in Supabase secrets, set by the maintainer; no personal data or keys in events; request context never leaks between requests (the runtime reuses the process).
- S4: Cron Monitors for the money and order crons: Sentry alerts when a job is missed or fails.
- S5 (later): Bruno collection, after Sentry ("depsues de sentry me gusaria ver lo de bruno de una vez").
