# Server-only objects in the internal schema

Roadmap #299, item 7 (#306). Worktree `supabase-health`. Scope B approved on 2026-11-11 (L3): server-only machinery moves to `internal`; server-owned domain records stay in `public`.
PR 1: cron leases (branch `chore/cron-leases`). PR 2: function moves, #435, `products_public` decision, convention. PR 3: table moves.

## Specs

- S1. "Investigá primero y proponeme el plan antes de escribir."
- S2. From #306: "Keep the Data API surface small: tables and functions that only the server uses move out of `public` into the existing `internal` schema." "`is_admin()` and `fn_current_account_is_active()` stay in `public`: RLS policies call them." Limit found in L2: PostgREST calls only functions in exposed schemas, so functions that Edge Functions call with `.rpc()` stay in `public`, executable only by `service_role`.
- S3. Rule approved (L3, scope B): a table moves to `internal` when its whole module is server-only machinery (inbox, job queue, event log, cache, lock). Moves: `webhook_deliveries`, `account_closures`, `connect_account_actionability`, `connect_account_events`, `connect_payout_events`, `checkout_recovery_shells`, `stripe_fee_reconciliation_jobs`. Stay in `public`: `connect_payout_runs`, `connect_payout_run_shipments`, `shipment_cancellation_operations`, `shipment_completion_events`, `push_tokens`, `push_deliveries`, `push_event_policy` (domain records, or a module whose tokens the client registers).
- S4. Cron leases (from the #306 and #309 comments): one `internal.cron_leases` table and one generic acquire and release pair replace the ten `system_settings` lease columns and their six functions. Leases keep their expiry (not advisory locks). Each job keeps today's lease length (auto-cancel orders and preparing 600 s, track-shipments preparing and shipped 300 s, checkout recovery 600 s), the holder-only release, the `UNAUTHORIZED` guard for non-service callers, and checkout recovery is still not acquired while `checkout_recovery_enabled` is false. The two unused flags `release_funds_running` and `return_delivery_timeout_running` are dropped (#25, #309).
- S5. Functions that move to `internal`: the ones PostgREST never calls (run directly by pg_cron, or called only by other SQL). Trigger functions and RPCs stay in `public`.
- S6. "#435: ¿lo sumo al PR 2?" Approved (L3): drop `internal.is_admin()` and `internal.fn_check_order_access(uuid)`.
- S7. `products_public` stays a `SECURITY DEFINER` view (approved, L3). The reason is recorded in `docs/decision-log.md` and on the view, and the advisor ERROR is listed as accepted in `docs/maintenance.md`. Reason: a `security_invoker` view needs a row policy on `products` for public listings; column grants are per role, not per row, and `authenticated` needs table-level SELECT for owners, so other users could read the hidden columns of public listings.
- S8. The convention is written in `supabase/AGENTS.md` and `docs/conventions.md`; #306 records the narrowed scope.
- S10. T6 plan approved (L20): `stripe-webhooks` enqueues fee jobs through a new service-only RPC instead of `.from()`; the leased claim returns a column table instead of the moved row type (same JSON); the three functions that only raise `STRIPE_FEE_LEASE_REQUIRED` are dropped; Bruno requests that read or write the job rows move to `scripts/verify/verify-stripe-fee-lease-recovery.ts`.
- S9. "recuerda que tienes que tomar en cuenat lo que dice el agents.md sobre 'cunado saber que es sobreingenieria' osea, no esojer la opcion 'x' nomas por comoditad."
