# Maintenance routine

A documented weekly (Monday) and monthly routine that any agent runs the same way: it collects the repository's state, reports what needs a decision with a recommendation, and the maintainer decides. Each area copies the dependency system: data that arrives on its own, a written procedure, and a fixed way to act.
Branch `docs/maintenance-routine`, main checkout. No roadmap: one feature, documentation and one skill, one session (L4).

OpenSSF Scorecard (https://scorecard.dev/) scores a public repository's supply-chain posture weekly. Design agreed with the maintainer:
  - Five systems. A dependencies (exists: workflows, `docs/dependencies.md`, `selene-dependency-review`). B security: draft Security Advisories, open secret scanning alerts, Supabase security advisors through the MCP. C backlog: new issues of the week, open critical and high, findings with no priority label, stale issues, Ideas whose "When to revisit" moment came, PRs open more than 7 days. D app health, light until go-live: failed runs on `main`, new Sentry issues, Supabase performance and health advisors; thresholds come with real traffic. E agent tools, monthly: `npx skills check`.
  - Weekly every Monday after the dependency workflows; monthly on the 1st or with the first Monday: the weekly checks plus `docs/dependencies.md` monthly steps, the local Supabase CLI against the CI pin, `HELD_BACK` blockers, `bun run worktree:clean` plan, and a "manual work that repeats" question (Google SRE toil review).
  - Session: collect (change nothing), report, decide, topic of the week, record. The report shows one line per OK section and detail only for items that need a decision, each with evidence, a recommendation and its reason, and must-have, nice-to-have, or overengineering. A check that cannot run is "Could not check" with the exact blocker.
  - Topic of the week (adapted "The Wheel"): the eight `area:*` labels in a fixed order, picked by ISO week number modulo 8 so every agent picks the same topic; the maintainer can swap it. Read-only, at most three observations.
  - Phase 2, after a few weeks of runs and with maintainer approval for CI changes: a Skills section in the weekly dependency report, `supabase db advisors` in CI, OpenSSF Scorecard, and later GitHub Agentic Workflows. Recorded as Idea issues, not built now. Agentic Workflows wait because each run costs tokens and an agent reading public issue text can be prompt-injected.
