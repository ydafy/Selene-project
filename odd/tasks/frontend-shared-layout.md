# Frontend shared/ by topic, with @/ imports (#291)

Item 7 of roadmap #228, the last one. Keeps `apps/frontend/src/shared/` for code that two or more features (or `app/` and a feature) use, groups `shared/ui` and `shared/utils` by topic, and converts relative imports that leave their top-level folder to `@/`, kept by an ESLint rule. Branch `refactor/frontend-shared-layout`, from `origin/main` 545a542a.

## Specs

- S1 (issue #291, item 1): "**Only shared code in `shared/`.** List every file under `apps/frontend/src/shared/` with the features that import it. A file used by one feature only moves into that feature (`features/<domain>/{components,hooks,lib,logic,utils}`), with `scripts/dev/move-files.ts`." Corrected by L2: `shared/utils/connect-onboarding-urls.ts` stays, because its only importer is `shared/hooks/use-connect-onboarding.ts`, which `app/`, profile, and orders use; moving it would make `shared/` import a feature. Smaller folders (`hooks/` with 21, `lib/`) stay flat unless a clear cluster shows up."
- S3 (issue #291, item 3): "**`@/` for imports that leave their top-level folder** (`app/`, `features/<domain>/`, `shared/`), converted in one pass and kept by an ESLint rule forbidding `../../`, as admin-web does after #221 (S11 of `odd/tasks/admin-web-layout.md`). By L2 the rule is the admin-web one (any relative import that leaves its top-level folder, not the `../../` string), and it also checks the first string argument of `mock.module(...)`, `jest.mock(...)`, and `require(...)`.
