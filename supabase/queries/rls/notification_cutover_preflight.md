## Interpret the result

- Compare relation, columns (especially `event_kind`, `source_event_key`, `event_payload`), policies, effective table/column privileges and named indexes against the migration preconditions. `n4a_constraints` reports presence and validation status for the four named N4a checks, not their expressions. `n5a_arbiter_matches` checks the named partial unique index against N5a's key order, uniqueness, valid/ready/immediate flags, two-key count and predicate. These are contextual catalog snapshots, **not migration execution or approval**. An absent relation or missing RPC signature is not a passing check; verify definitions independently.
- `triggers` is limited to `set_product_in_dispute`, `notify_dispute_opened`, and legacy `tr_on_dispute_opened` **on `public.disputes`**, not notifications. Compare enabled state, function identity and the `after_insert` flag (row-level, not BEFORE or INSTEAD OF) with N5f. `n5f_function_present` reports whether `public.fn_notify_dispute_opened()` exists (expected false before N5f); the new trigger should likewise be absent before N5f. Check the existing `set_product_in_dispute` function identity and flags before applying N5f.
- `rpcs` enumerates the exact N4b signature set and flags missing entries. Review `security_definer`, default count, and effective EXECUTE for anon, authenticated and service_role. For `fn_seller_submit_return_evidence(uuid,text[],text)`, N5h specifically requires **one** default, `SECURITY DEFINER`, exact `search_path=public, pg_temp` configuration and service-only EXECUTE before its own change. Null flags mean the function was not found; do not interpret them as false. This diagnostic intentionally does not export arbitrary `proconfig` or function bodies.
- N4b **expects legacy broad anon/authenticated INSERT grants and the legacy `notifications_all` policy in its preflight before it revokes/replaces them**. Their presence in an uncut-over database is not a conflict. N5h instead requires the restrictive post-N4b privileges and the N4a unique arbiter. Compare each result against the correct phase; do not apply N5h ahead of its prerequisites.
- Check cron jobs manually in the intended project's Dashboard; this query does not inspect cron schemas or expose commands. Verify Edge Function deployments and versions separately.
